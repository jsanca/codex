OBSERVATIONS
------------
- module-info.java: both requires changed to requires transitive because the public API
  exposes Actor (from codex.fundamentum) and SiteKey/ContentTypeKey/ContentItemKey (from
  codex.codex). Without transitive, callers of codex-custos would need to declare those
  dependencies themselves to compile against the API.

- AccessDeniedException now carries Optional<AccessDecision.Denied> so callers can inspect
  actor, permission, resource, and reason without parsing the message string. The raw-message
  constructors still exist and return Optional.empty() for decision(). This preserves backward
  compatibility while meeting the assertSame requirement from the task.

- reason validation: blank reasons now rejected in both Granted and Denied. This is consistent
  with PermissionKey (which also rejects blank) and the task's intent that denied decisions
  preserve a "useful" reason.

- SecurityEvaluationContext.empty() returns a singleton (EmptyContext.INSTANCE). The singleton
  test passes. The interface is intentionally kept open for future context fields (timestamps,
  step-up tokens, tenant context) — none added per task scope.

- PermissionEvaluator and AccessDecisionService were reviewed for API name consistency with
  ADR-009. Both match. No changes needed.
