SUMMARY
-------
Added the Permissions catalog — a final utility class with 20 public static final
PermissionKey constants covering the 5 namespaces from ADR-009: site (5), contentType (4),
contentItem (6), permission (3), role (2).

8 new tests in PermissionsTest verify canonical string values by namespace, catalog size,
uniqueness of all constants, and that the class has only a private constructor. No string
duplication: tests reference the constants by field name, not by re-declaring the string value.
Test count grew from 37 to 45. Build green across full reactor.

OBSERVATIONS
------------
- The catalog is intentionally flat (no grouping enum or inner class). Constants are
  organized by comment block (site / contentType / contentItem / permission / role).
  This is the simplest structure that satisfies the task without premature abstraction.

- The `allConstants()` test helper uses reflection to collect all public static final
  PermissionKey fields. This makes the distinctness and catalog-size assertions resilient
  to future additions — adding a constant will automatically update the reflected list,
  and the catalog-size test will then fail explicitly, requiring a deliberate update.

- Implication semantics (update implies read, publish implies read, publish does NOT imply
  update) are documented in JavaDoc only, as required by ADR-009. No enforcement logic was
  added — that belongs in Phase 1+ resolvers.

- The nonInstantiable test verifies the constructor is private via reflection, not by
  trying to invoke it. Invoking a private constructor via setAccessible(true) succeeds
  unless the constructor explicitly throws — which would be unnecessary defensive code
  for a scenario that cannot happen in normal use.
